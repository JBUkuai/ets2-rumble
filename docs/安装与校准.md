# ETS2 Rumble 安装与手感校准

版本 0.2.0（图形界面 + 握把马达）

---

## 1. 它能做什么、不能做什么

**能做**

- 读取 scs-sdk-plugin 写入的共享内存 `Local\SCSTelemetry`，30Hz 轮询（可配置）。
- 在三类事件触发时让 Xbox 兼容手柄的握把马达震动：换挡冲击、急刹、碰撞/大颠簸。
- 拨转向灯、开关雨刮时给一次轻震（默认 20% 强度），由 SCS SDK 的开关状态字段驱动。
- 所有强度、时长、阈值、冷却都在 `config.json` 里，保存即热重载。
- 图形界面里可以直接开关各类功能、拖动滑杆调强度/时长、看实时滚动日志（最近 100 条）、右上角中英文切换；改完自动保存并立即生效，不需要重启程序。
- 游戏未启动 / 退出 / 读档时不会崩，自动等待并重连。
- 日志落在 `logs/rumble.log`，记录每次触发时的遥测值。

**不能做（MVP 边界，别期待）**

- **不做扳机脉冲震动**。XInput 标准接口只能控制握把马达；扳机震动需要 HID 或 Windows.Gaming.Input，属于二期。
- **拿不到真正的“碰撞事件”**。SCS Telemetry SDK 里没有碰撞通道（我核对过全部头文件，只有货物损伤 `job.cargo.damage`）。本程序的“颠簸/碰撞”是从**线加速度突变**推断的，货物损伤增量仅作辅助证据。
- 不注入游戏、不 Hook `xinput1_3.dll`，不绕过 Steam Input。
- 不保证所有第三方手柄都支持：只要求它工作在 **XInput 模式**。

## 2. 安装插件（只需一次）

1. 打开游戏目录，例如：
   `E:\SteamLibrary\steamapps\common\Euro Truck Simulator 2\bin\win_x64\`
2. 如果没有 `plugins` 文件夹，手动新建。
3. 把 `scs-telemetry.dll`（64 位版）复制进 `bin\win_x64\plugins\`。
   只需要这一个文件，不要复制 32 位目录里的那个。
4. 启动游戏进入驾驶舱。游戏会提示 **“SDK has been activated” / 高阶模式已启动**，属正常现象，每次启动都会弹。

> 如果没弹提示，说明插件没被加载：检查是不是放到了 `bin\win32`、文件名是否被改、游戏是否是 64 位。

**验证数据确实在写：**

```
Ets2Rumble.exe --probe --probe-seconds 10
```

能持续打印 `sdkActive=True`、挡位、车速、加速度，就说明整条链路通了。

---

## 3. 必须关闭 Steam Input

如果 Steam Input 开着，它会接管 XInput 设备，导致 `XInputSetState` 调用无效——表现是“程序有日志、手柄不震”。

操作路径（Steam 新版界面）：

**Steam → 设置 → 控制器 → 为 Xbox 控制器启用 Steam 输入 → 关闭**

同时确认：**Steam → 设置 → 控制器 → 通用控制器支持** 中，没有把该手柄强行套用成其他配置。

改完建议重启 Steam 和目标程序。

## 4. 运行

自包含发布版无需安装 .NET，**直接双击 `Ets2Rumble.exe`** 就会打开图形界面。

界面布局：

- 左列：换挡 / 急刹 / 颠簸 三张卡片，以及转向灯、雨刮、大灯、远光、双闪、手刹的开关
- 右列：运行状态（数据源、手柄、车速、当前输出）、震动总开关、静音测试、实时日志
- 右上角：中文 / EN 切换；窗口按钮在更右侧
- 底部：配置文件路径；参数改动后显示“改动已保存并生效”

所有改动**自动保存**到 `config.json` 并立即作用于引擎（主循环读到新版本即切换），关掉界面再打开会保留上次设置。

常用参数（需要命令行时）：

| 参数 | 作用 |
|---|---|
| 无参数 | 打开图形界面：读共享内存 + 驱动手柄 |
| `--sim` | 图形界面 + 模拟数据源，不依赖游戏（无游戏时预览界面/试滑杆） |
| `--console` | 不开界面，按 0.1.0 的控制台方式运行（内存占用最低） |
| `--probe --probe-seconds 15` | 只读遥测并打印，不震动（排查链路，控制台） |
| `--no-output` | 不驱动手柄，只写日志（安全试阈值） |
| `--config 路径` | 指定其他配置文件 |

退出：直接关窗口（会把马达归零并保存配置）；控制台模式用 `Ctrl+C`。

> 资源占用参考：图形界面约 220–230 MB 内存、单核 1% CPU；`--console` 约 30 MB。
> 如果更在意内存，用 `--console` 跑，功能一致，只是没有界面。

## 5. 校准流程（建议严格按顺序）

### 第 1 步：确认自检通过

启动后日志里应有：

```
结构体偏移自检通过：sdkActive=0 paused=4 time=8 gear=504 speed=948 userBrake=964 accel=1892
```

这行是拿 `Marshal.OffsetOf` 和插件头文件逐项比对的，不通过程序会直接退出，不会带着错位去震动。

### 第 2 步：先看数据，别急着震

在界面右侧打开**静音测试**（或把 `config.json` 里改两处）：

```json
"output": { "dryRun": true },
"log": { "telemetrySampleMs": 200 }
```

跑一段包含换挡、急刹、压坑的路，然后看日志里的 `[采样]`：

- 确认车速量级正确：高速上应接近仪表盘读数（内部是 m/s，日志已换算 km/h）。
- 确认刹车踏板在踩下时接近 1.00。
- 确认加速度三轴在正常巡航时很小，压到坑/撞护栏时会出现明显尖峰。

> 加速度轴指向在 SDK 文档中没有定义（只写了 vehicle space），所以本程序**不依赖具体轴**：先对三轴做高通（减去慢速基线）再取模长。你把三轴原始值发我，我可以按你的车进一步调。

### 第 3 步：分别调三类事件

每次只改一类，改完保存（热重载，日志会打印“配置已热重载”）。

**换挡冲击**

| 参数 | 含义 | 调整方向 |
|---|---|---|
| `shift.minSpeedKph` | 低于该车速不触发 | 停车挂挡乱震就调高 |
| `shift.strength` | 基础强度 0..1 | 太轻加 0.05，太重减 0.05 |
| `shift.durationMs` | 包络时长 | 短促 80~120；闷 150~200 |
| `shift.cooldownMs` | 最小间隔 | 连续降挡只想要一下，就调大到 400 |

**急刹**

| 参数 | 含义 | 调整方向 |
|---|---|---|
| `brake.pedalThreshold` | 踏板触发阈值 | 键盘玩家一脚就是 1.0，默认 0.85 合适 |
| `brake.decelThresholdMps2` | 减速度阈值（m/s²） | 4 ≈ 温和急刹；想只在重刹时震就调到 6 |
| `brake.holdMs` | 条件需持续多久 | 防止单帧抖动误触发，默认 80 |
| `brake.strength` / `durationMs` | 强度 / 时长 | 一次刹车只触发一下（已做锁存） |

**颠簸 / 碰撞**

| 参数 | 含义 | 调整方向 |
|---|---|---|
| `bump.thresholdMps2` | 加速度突变阈值 | 4 偏灵敏；只想大坑/撞车才震，调到 7~9 |
| `bump.cargoDamageDelta` | 货物损伤增量辅证 | 0.005 很灵敏；不想靠它触发可设 0.1（实际等于关闭） |
| `bump.minSpeedKph` | 低速不触发 | 避免挪车时乱震 |
| `bump.strength` / `durationMs` | 强度 / 时长 | 撞击可以给到 0.9 / 300ms |

### 第 4 步：整体增益

`output.leftGain` / `output.rightGain`（0..1）统一缩放左右马达。想让震动更“偏一侧”可以只改其一（目前两条马达输出相同）。

### 小部件开关（转向灯 / 雨刮 / 大灯 / 远光 / 双闪 / 手刹）

拨杆或按钮一动就震一下。普通开关默认 30% 强度、150ms；手刹单独一组，45% / 600ms（模拟真实拉杆的动作长度）。

| 参数 | 含义 | 默认 |
|---|---|---|
| `switches.enabled` | 总开关 | true |
| `switches.blinkers` | 左/右转向灯 | true |
| `switches.wipers` | 雨刮 | true |
| `switches.headlights` | 大灯（近光） | true |
| `switches.highBeam` | 远近光切换（远光） | true |
| `switches.hazardLights` | 双闪 | true |
| `switches.strength` | 上面这些开关的强度 | 0.30 |
| `switches.durationMs` | 上面这些开关的时长 | 150 |
| `switches.parkingBrake` | 手刹（驻车制动） | true |
| `switches.parkingBrakeStrength` | 手刹强度 | 0.45 |
| `switches.parkingBrakeDurationMs` | 手刹时长 | 600（真实拉杆约 0.5~0.7 秒） |

对应的 SDK 字段：`truck.lblinker` / `truck.rblinker` / `truck.wipers` / `truck.light.beam.low` /
`truck.light.beam.high` / `truck.hazard.warning` / `truck.brake.parking`。

> **为什么不会跟着双闪“哒哒”震：** 用的是 `truck.lblinker` / `truck.rblinker`（拨杆开关状态，SDK 原文明确说它不随灯闪烁变化），
> 而不是 `truck.light.lblinker`（灯当前是否亮，会随闪烁翻转）。后者一用就会每次闪灯都触发。
>
> **双闪去重：** 打开双闪时游戏可能同时把左右转向灯置为 true，程序会跳过同一帧的转向灯事件，
> 保证一次双闪只产生一下震动。
>
> 日志里看到 `[事件] 手刹 强度 0.45 时长 600ms | 开` 就说明生效了。

## 6. 日志字段

文件：`logs/rumble.log`（超过 5MB 自动轮转为 `rumble.log.1`）。

- `[事件] 换挡 强度 0.35 时长 120ms | 挡位 2->3，车速 72 km/h，转速跳变 0`
- `[事件] 急刹 强度 0.60 时长 220ms | 踏板 1.00，减速度 5.2 m/s²，车速 53 km/h`
- `[事件] 颠簸 强度 0.80 时长 260ms | 加速度突变 7.9 m/s²，车速 44 km/h，原始轴 0.1/0.0/-8.2`
- `[采样] 挡位 6 车速 78.3km/h 转速 1450 踏板 0.00/0.00 加速度 0.12/-0.05/0.33 角加速度 ... 货损 0.0000`
- `遥测时间戳 1000ms 未更新（游戏暂停、读档或菜单），已清空震动`
- `XInputSetState 失败（错误码 1167），手柄可能已断开，2 秒后重试`

> 错误码 1167 = `ERROR_DEVICE_NOT_CONNECTED`，通常就是手柄断了或 Steam Input 接管。

## 7. 已知问题与兼容性

| 现象 | 原因 | 处理 |
|---|---|---|
| 有日志但手柄不震 | Steam Input 接管 / 手柄是 DInput 模式 | 关闭 Steam Input；手柄切 XInput 模式 |
| `--probe` 打不开共享内存 | 游戏没运行，或插件没放进 `plugins` | 见第 2 节 |
| `sdkActive=False` | 插件加载了但未完成初始化 | 进一次驾驶舱（读档后才会开始跑帧） |
| 每次开游戏弹 SDK 提示 | 插件行为，非本程序 | 点确定即可 |
| 换挡震动过于频繁 | 连续降挡/自动挡换挡密集 | 调大 `shift.cooldownMs` |
| 蓝牙连接时震动时有时无 | 蓝牙链路与驱动层差异 | MVP 仅以有线验证；蓝牙问题不承诺 |
| 游戏 1.62 与插件 1.12.1 | 插件较旧，但源码里版本检查只做分支不做拒绝 | 实测可用；若某版本失效，需要换维护分支或自行编译插件 |
| 英文界面下日志仍为中文 | 日志与事件文本由引擎直接生成，未做翻译 | 属已知限制；界面标签、状态、按钮已全部切换，日志仅作诊断用 |
| 界面内存约 220 MB | WPF 运行时本身占大头 | 需要更省内存时用 `--console`（约 30 MB） |

**退出与重连**

- 游戏退出：共享内存消失，程序每 1 秒重试，日志出现一次警告后静默等待。
- 游戏重新启动：自动连上，日志打印“遥测已连通”。
- 手柄拔出：输出层每 2 秒重扫，回来即恢复。
- 程序本身崩溃不会影响游戏（纯外部读取）。

## 8. 二期（不在这次范围）

1. 扳机脉冲震动：需要 HID / `Windows.Gaming.Input`，参考 X1nput 的 Hook 思路，但不 Hook 游戏。
2. HTTP 回退数据源：`http://localhost:25555/api/ets2/telemetry`，独立线程 + 单槽位缓存，字段需先核实。
3. 多马达差异化输出（左右握把不同强度、按事件类型分配）。
